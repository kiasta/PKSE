## 2. What is different from Gen 1

Nine things. Everything else you can copy.

| # | Difference | Consequence |
|---|---|---|
| 1 | **Held items exist.** `PK2.HeldItem` at body `0x01`. | `hasHeldItem()` returns **true**. Gen 2 item id space. |
| 2 | **Friendship exists.** Body `0x1B`. | `hasFriendship()` → **true**. |
| 3 | **Pokérus exists.** Body `0x1C`. | `hasPokerus()` → **true**. |
| 4 | **Met data exists — Crystal only.** Body `0x1D`–`0x1E`. | `hasMetData()` → `CaughtData != 0`. GS writes nothing here. |
| 5 | **Gender is derived, not stored** — from `IV_ATK` vs the species gender ratio. | `hasStoredGender()` → **false**, same as Gen 1, but the *ratio* now matters. |
| 6 | **SpA and SpD are separate BASE stats but share one DV and one EV.** | Six stat slots, five DVs, five EVs. Not Gen 1's single Special. |
| 7 | **Eggs exist**, flagged in the **list header** (`0xFD`), not in the body. | `isEgg()` reads the header byte. Round-tripping it needs care. |
| 8 | **The current-box mirror is NOT authoritative** (opposite of Gen 1). | Read boxes from the bank only. See §4.4 — this one will bite you. |
| 9 | **Three extra item pouches**, one of them positionally indexed. | See §9. |

Plus: 14 boxes of 20 (int) or 9 of 30 (JP) rather than 12/8; a 16-bit checksum written twice
rather than one byte; and a **Korean** locale that exists for GS only and has its own oddball
checksum.

## 3. Save file geometry

### 3.1 Sizes

```
SIZE_G2RAW_U = 0x8000    // 32768 — International and Korean
SIZE_G2RAW_J = 0x10000   // 65536 — Japanese
```

*(PKHeX `SaveUtil.cs`.)* **The names are misleading: PKHeX accepts EITHER size for every layout**
(`IsG2` probes international GS, international Crystal, Japanese GS, Japanese Crystal, in that order,
whatever the length), and so does PKSE (`GEN2_SAVE_SIZE` / `GEN2_SAVE_SIZE_DOUBLED`). A Japanese
cartridge's SRAM is 32 KiB, every Japanese offset sits below 0x8000, and tying the layout to the size
refused ordinary Japanese saves. The one Japanese field past 0x8000 — Crystal's trainer gender — is
bounds-checked where it is used.

### 3.2 Detection

PKHeX identifies a Gen 2 save by probing **two Pokémon-list headers** at known offsets. There is
no magic number and no version byte, exactly as in Gen 1.

```csharp
// SaveUtil.cs
private static bool IsListValidG12(ReadOnlySpan<byte> data, int offset, byte maxCount)
{
    byte count = data[offset];
    return count <= maxCount && data[offset + 1 + count] == 0xFF;
}
private static bool HasListAt(data, int offset1, int offset2, byte maxCount) =>
    IsListValidG12(data, offset1, maxCount) && IsListValidG12(data, offset2, maxCount);

IsG2GSINT      => HasListAt(data, 0x288A, 0x2D6C, 20);   // party, currentbox
IsG2CrystalINT => HasListAt(data, 0x2865, 0x2D10, 20);
IsG2GSJPN      => HasListAt(data, 0x2D10, 0x283E, 30);
IsG2GSKOR      => HasListAt(data, 0x2DAE, 0x28CC, 20);
IsG2CrystalJPN => HasListAt(data, 0x2D10, 0x281A, 30);
```

**Probe order matters** — PKHeX tries International GS, International Crystal, Japanese GS,
Japanese Crystal, then Korean GS. Follow that order.

> **Note the collision.** `IsG2GSJPN` and `IsG2CrystalJPN` both probe `0x2D10` as one of their two
> offsets (it is the JP `CurrentBox` for both). They are separated by the *other* offset — the
> party at `0x283E` vs `0x281A`. Probing only one list would make GS and Crystal
> indistinguishable in Japanese.

### 3.3 The two box banks

Boxes are split across two SRAM banks, exactly as in Gen 1 but with a different split index:

```csharp
// SAV2.cs
int splitAtIndex = Japanese ? 6 : 7;

private int GetBoxRawDataOffset(int i, int splitAtIndex)
{
    if (i < splitAtIndex)
        return 0x4000 + (i * (SIZE_BOX_LIST + 2));
    return 0x6000 + ((i - splitAtIndex) * (SIZE_BOX_LIST + 2));
}
```

Note the **`+ 2` stride padding** between consecutive box lists — the list itself is
`SIZE_BOX_LIST` bytes, but boxes are laid out every `SIZE_BOX_LIST + 2` bytes.

Worked out:

| Locale | Boxes | Slots/box | `SIZE_BOX_LIST` | Stride | Bank 0 (`0x4000`) | Bank 1 (`0x6000`) |
|---|---|---|---|---|---|---|
| International / Korean | 14 | 20 | **1102** | 1104 | boxes 0–6 | boxes 7–13 |
| Japanese | 9 | 30 | **1352** | 1354 | boxes 0–5 | boxes 6–8 |

```
SIZE_BOX_LIST   = ((StringLength * 2) + SIZE_2STORED + 1) * BoxSlotCount + 2
                = ((11*2) + 32 + 1) * 20 + 2 = 55 * 20 + 2 = 1102     (international)
                = ((6*2)  + 32 + 1) * 30 + 2 = 45 * 30 + 2 = 1352     (Japanese)

SIZE_PARTY_LIST = ((StringLength * 2) + SIZE_2PARTY + 1) * 6 + 2
                = ((11*2) + 48 + 1) * 6 + 2 = 71 * 6 + 2 = 428        (international)
                = ((6*2)  + 48 + 1) * 6 + 2 = 61 * 6 + 2 = 368        (Japanese)
```

Bounds check (both fit their banks):
`0x4000 + 7×1104 = 0x5E30 < 0x6000` ✓  `0x6000 + 7×1104 = 0x7E30 < 0x8000` ✓
`0x4000 + 6×1354 = 0x5FBC < 0x6000` ✓  `0x6000 + 3×1354 = 0x6FDE` ✓

### 4.4 ⚠ The current-box mirror trap — Gen 2 is the OPPOSITE of Gen 1

PKSE's Gen 1 code reads the current box from the **mirror** at `Offsets.CurrentBox`, because in
Gen 1 the mirror is the fresh copy (the game only flushes to the bank on a box change). That is
correct for Gen 1 and PKHeX does the same:

```csharp
// SAV1.cs — Gen 1 reads the MIRROR for the current box
if (current < BoxCount) // Load Current Box
{
    var src = Data.Slice(Offsets.CurrentBox, stored);
    ...
}
```

**Gen 2 does not work that way, and PKHeX says so explicitly:**

```csharp
// SAV2.cs — Initialize()
for (int i = 0; i < BoxCount; i++)
{
    int ofs = GetBoxRawDataOffset(i, splitAtIndex);
    ...  // every box, including the current one, comes from the BANK
}

// Don't treat the CurrentBox segment as valid; Stadium ignores it and will de-synchronize it.
// The main box data segment is the truth, the CurrentBox copy is not always up-to-date.
// When exporting an updated save file in this program, be nice and re-synchronize.
```

On write, the mirror is refreshed as a courtesy:

```csharp
bool written = PokeList2.MergeSingles(src, dest, StringLength, boxSlotCount, false);
if (written && i == CurrentBox)
    dest.CopyTo(Data[Offsets.CurrentBox..]);
```

**So for Gen 2: read the bank, write the bank, then copy the current box's bank bytes over the
mirror.** Carrying the Gen 1 habit across gives you a stale box whenever Stadium has touched the
save.

There is also **no `boxesInitialized` bit** in Gen 2's read path — that is a Gen 1 concept.

## 5. The PK2 entity

### 5.1 Sizes

```cpp
// PKHeX PokeCrypto.cs
SIZE_2STORED  = 32   // 0x20  box body
SIZE_2PARTY   = 48   // 0x30  party body — what a single-entry list carries
SIZE_2ULIST   = 73   // 1 + 2 + 48 + 11 + 11   international
SIZE_2JLIST   = 63   // 1 + 2 + 48 +  6 +  6   Japanese
SIZE_2STADIUM = 60   // Stadium 2 — out of scope
```

Compare Gen 1: `33 / 44 / 69 / 59`. **The box body shrank by one byte and the party body grew by
four.** Do not reuse Gen 1's constants.

### 5.2 The PokeList2 wrapper

Same structure as PokeList1:

```
u8              count of slots filled
u8[capacity+1]  species marker per slot, then a 0xFF cap byte
body[capacity]  SIZE_2STORED (boxes) or SIZE_2PARTY (party)
str[capacity]   OT names,   StringLength bytes each
str[capacity]   nicknames,  StringLength bytes each
```

```csharp
// PokeList2.cs
public const byte SlotEmpty = 0xFF;
public const byte SlotEgg   = 0xFD;
private static bool IsPresent(byte marker) => marker is not (0 or SlotEmpty);
private static bool IsEgg(byte marker) => marker == SlotEgg;

public static int GetListLength(int capacity, int sizeBody, int stringLength)
    => 1 + (capacity + 1) + (sizeBody * capacity) + (stringLength * capacity * 2);
```

For a **single-entry** list (`capacity = 1`, party body):
`1 + 2 + 48 + 11 + 11 = 73` international, `1 + 2 + 48 + 6 + 6 = 63` Japanese. ✓

Offsets inside a single-entry list:

```
0       count            (1)
1       species marker   (internal index, 0xFF empty, 0xFD egg)
2       0xFF             (list cap)
3       body             48 bytes
51      OT name          11 (int) / 6 (JP)
51+L    nickname         same width
```

> **`SlotEgg` = `0xFD` is the whole egg mechanism.** `PK2.IsEgg` in PKHeX is a plain C# property
> **not backed by the data buffer** — it is set from the list header on read and written back to
> the header on write. If you store the marker as the species and drop the `0xFD`, every egg in
> the save silently hatches.

Header validation, which is also what save detection uses:

```csharp
public static bool IsValidHeader(ReadOnlySpan<byte> input, int capacity)
{
    var count = input[0];
    if (count > capacity) return false;
    for (int i = 0; i < capacity; i++)
    {
        var mark = input[1 + i];
        if (IsPresent(mark) != (i < count)) return false;   // presence must match the count
    }
    return true;
}
```

### 5.4 DVs and derived values (shared with Gen 1)

```csharp
// GBPKM.cs — identical for PK1 and PK2
IV_ATK = (DV16 >> 12) & 0xF
IV_DEF = (DV16 >>  8) & 0xF
IV_SPE = (DV16 >>  4) & 0xF
IV_SPC = (DV16 >>  0) & 0xF
IV_HP  = ((IV_ATK & 1) << 3) | ((IV_DEF & 1) << 2) | ((IV_SPE & 1) << 1) | (IV_SPC & 1)   // derived
IV_SPA = IV_SPC;  IV_SPD = IV_SPC (setter is a NO-OP)
EV_SPA = EV_SPC;  EV_SPD = EV_SPC (setter is a NO-OP)
```

Gender, from the gender ratio in the personal table:

```csharp
int gv = PersonalInfo.Gender;
return gv switch {
    RatioMagicGenderless => 2,
    RatioMagicFemale     => 1,
    RatioMagicMale       => 0,
    _ => IV_ATK > (gv >> 4) ? 0 : 1,     // male if ATK DV exceeds the threshold
};
```

Unown form, from the DVs:

```csharp
formeVal  = ((atk & 6) << 5) | ((def & 6) << 3) | ((spe & 6) << 1) | ((spc & 6) >> 1);
form      = formeVal / 10;
```

Hidden Power, shiny test and PP-Up handling are all `GBPKM` too, i.e. **already in PKSE for Gen 1**.

### 5.5 The stat formula — identical to Gen 1

```csharp
// GBPKM.cs — used by BOTH PK1 and PK2
protected static ushort GetStat(int baseStat, int iv, int effort, byte level)
{
    byte firstSquare = (byte)Math.Min(255, Math.Ceiling(Math.Sqrt(effort)));
    effort = firstSquare >> 2;
    return (ushort)((((2 * (baseStat + iv)) + effort) * level / 100) + 5);
}

public override void LoadStats(IBaseStat p, Span<ushort> stats)
{
    var lv = CurrentLevel;                                    // recomputed from EXP, NOT Stat_Level
    stats[0] = GetStat(p.HP,  IV_HP,  EV_HP,  lv) + (5 + lv); // HP gets the extra term
    stats[1] = GetStat(p.ATK, IV_ATK, EV_ATK, lv);
    stats[2] = GetStat(p.DEF, IV_DEF, EV_DEF, lv);
    stats[3] = GetStat(p.SPE, IV_SPE, EV_SPE, lv);
    stats[4] = GetStat(p.SPA, IV_SPA, EV_SPA, lv);            // base SPA, shared DV/EV
    stats[5] = GetStat(p.SPD, IV_SPD, EV_SPD, lv);            // base SPD, shared DV/EV
}
```

> **This is the single biggest reuse win.** `Pokemon1RBY::recalculateStats()` already implements
> this exactly. The *only* change for Gen 2 is that SPA and SPD read **different base stats** while
> still sharing the DV and EV — Gen 1 has one Special base stat for both.
>
> It is also your strongest verification lever: a PK2 **party** record stores the five battle
> stats the game computed, so recomputing and comparing proves the tables, the big-endian reads,
> the DV unpack and the formula all at once — the same check that verifies Gen 1.

## 6. Checksums

### 6.1 The entity has none

`GBPKM.RefreshChecksum()` is `{ }` and `ChecksumValid => true`. Repurpose `refreshChecksum()` to
re-sync the PokeList2 header, exactly as `Pokemon1RBY` does — that keeps the ~200 existing
"mutate then refreshChecksum" call sites correct.

Override `isStructurallyValid()`, because `Bank::load` gates on it and there is no checksum:

```cpp
bool isStructurallyValid() const noexcept override {
    const uint8_t mark = rd8(1);
    return mark != 0 && mark != 0xFF && speciesID() != 0 && speciesID() <= MAX_SPECIES_GEN2;
}
```

### 6.2 The save checksum

```csharp
// SAV2.cs
private ushort GetChecksum()
{
    ushort sum = 0;
    for (int i = Offsets.Trainer1; i <= Offsets.AccumulatedChecksumEnd; i++)
        sum += Data[i];
    return sum;
}

protected override void SetChecksums()
{
    ushort checksum = GetChecksum();
    WriteUInt16LittleEndian(Data[Offsets.OverallChecksumPosition..],  checksum);
    WriteUInt16LittleEndian(Data[Offsets.OverallChecksumPosition2..], checksum);
}
```

Three details that matter:

1. **Inclusive range.** `i <= AccumulatedChecksumEnd`, not `<`.
2. **The sum is 16-bit, and it wraps.** Gen 1's is one byte and inverted (`~sum`). Different
   algorithm; do not copy Gen 1's.
3. **The checksum itself is written LITTLE endian**, even though every entity field is big endian.
   PKHeX uses `WriteUInt16LittleEndian` here. Getting this backwards produces a save the game
   rejects.

### 6.3 Mirror regions written on save

`GetFinalData()` copies chunks of the trainer region to backup locations. **These are not
optional** — the games read them.

```csharp
if (Japanese)
{
    // Crystal:  Data[Trainer1 .. Trainer1+0xADA]  ->  0x7209
    // GS:       Data[Trainer1 .. Trainer1+0xC83]  ->  0x7209
}
else if (Korean)
{
    var sum = GetKoreanChecksum();
    WriteUInt16LittleEndian(Data[0x7E6B..], sum);
}
else // International
{
    // Crystal: Data[0x2009 .. 0x2009+0xB7A] -> 0x1209
    // GS: five separate ranges
    //   0x2009..0x222F -> 0x15C7
    //   0x222F..0x23D9 -> 0x3D69
    //   0x23D9..0x2856 -> 0x0C6B
    //   0x2856..0x288A -> 0x7E39
    //   0x288A..0x2D69 -> 0x10E8
}
```

The Korean oddball checksum:

```csharp
private ushort GetKoreanChecksum()
{
    ushort sum = 0;
    // (start, endExclusive) pairs
    (0x106B, 0x1533), (0x1534, 0x1A12), (0x1A13, 0x1C38), (0x3DD8, 0x3F79), (0x7E39, 0x7E6A)
    foreach pair: for (i = start; i < endExclusive; i++) sum += Data[i];
    return sum;
}
```

> **Order of operations on save:** apply all block writes → `SetChecksums()` → then the mirror
> copies. PKHeX calls `SetChecksums()` *before* the copies, so the mirrors carry the fresh
> checksum bytes where they overlap.

## 7. Text

`StringConverter2`. Same encoding *shape* as Gen 1 — one byte per glyph, terminator `0x50`,
in-game-trade OT marker `0x5D` — but **a different table**, and there are three of them:

```csharp
private static ReadOnlySpan<char> GetDict(int language) => language switch
{
    1        => TableJP,
    3 or 5   => TableFRE,   // French and German share a table
    4 or 7   => TableITA,   // Italian and Spanish share a table
    _        => TableEN,
};
```

`TableEN` (`StringConverter2.cs`), the region that differs from Gen 1:

```
0x80-0x99  'A'..'Z' then '(' ')' ':' ';' '[' ']'
0xA0-0xB9  'a'..'z'
0xBA-0xCF  à è é ù À Á Ä Ö Ü ä ö ü È É Ì Í Ñ Ò Ó Ù Ú á
0xD0-0xD6  LIGATURE codes 0..6           <- Gen 2 only
0xDF       '←'
0xE0-0xEF  ' ' PK MN '-' '+' ? ! . & é → ▷ ▶ ▼ ♂
0xF0-0xFF  ¥ × . / , ♀ '0'..'9'
0x4E       RET (line break)
0x5D       TOT (in-game-trade OT marker)
0x7A-0x7F  … ┌ ─ ┐ │ └ ┘
```

Field widths:

```
MaxStringLengthTrainer  = Japanese || Korean ? 5 : 7
MaxStringLengthNickname = Japanese || Korean ? 5 : 10
StringLength (buffer)   = Japanese ? 6 : 11
Box name buffer         = Korean ? 17 : 9   (max 8 characters)
```

**Ligatures.** Gen 2 encodes some two-character sequences (`ｅｒ`, `ｒｅ`, …) as single bytes
`0xD0`–`0xD6`. Box names go through `InflateLigatures` / `DeflateLigatures`:

```csharp
public string GetBoxName(int box)
{
    var result = GetString(GetBoxNameSpan(box));
    if (!Korean) result = StringConverter2.InflateLigatures(result, Language);
    return result;
}
public void SetBoxName(int box, ReadOnlySpan<char> value)
{
    const int maxLen = 8;
    Span<char> deflated = stackalloc char[maxLen];
    int len = StringConverter2.DeflateLigatures(value, deflated, Language);
    SetString(span, deflated[..len], maxLen, StringConverterOption.Clear50);
}
```

> **Ligatures are optional for a first pass.** Skipping them means an affected box name reads with
> a placeholder glyph rather than the two characters it stands for. It does **not** corrupt the
> save as long as you preserve the byte on round trip. Add a `Gen2Text.h` entry that maps
> `0xD0`–`0xD6` to a stable placeholder, and note it as deferred.

Follow the Gen 3 lesson ([manual ch. 07](../manual/07-data-tables.md)): **one table, one header,
`include/Utils/Gen2Text.h`.**
The Gen 3 charset once existed as four ad-hoc subsets and the damage was invisible for months.

Terminator policy, from `GBPKML`:

```csharp
private void SetStringKeepTerminatorStyle(ReadOnlySpan<char> value, Span<byte> exist)
{
    bool zeroed = exist.Contains<byte>(0);
    var option = zeroed ? StringConverterOption.ClearZero : StringConverterOption.Clear50;
    SetString(exist, value, value.Length, option);
}
```

**Preserve the existing terminator style.** Writing `0x50` where the game left `0x00` is one of the
five bugs an unedited round trip of a real Gen 1 save exposed.

## 9. Items

Five pouches. `PlayerBag2.cs`:

```csharp
new(offsets.PouchTMHM, 57, 99, info, TMHMs),
new(offsets.PouchItem, 20, 99, info, Items),
new(offsets.PouchKey,  26, 99, info, KeyItems),
new(offsets.PouchBall, 12, 99, info, Balls),
new(offsets.PouchPC,   50, 99, info, PCItems),
```

Three **different on-disk encodings**, all in `InventoryPouchGB.cs`:

**(a) Normal pouches** (Items, Balls, PC) — count-prefixed `{id, count}` pairs:

```
data[0]              = number of entries
data[1 + i*2]        = item id
data[2 + i*2]        = count
data[1 + 2*count]    = 0xFF   (terminator)
```

**(b) Key Items** — count-prefixed **id-only** list, quantity is implicitly 1:

```
data[0]          = number of entries
data[1 + i]      = item id
data[1 + count]  = 0xFF
```

**(c) TM/HM pouch** — **positionally indexed**, not a list:

```
data[i] = quantity of the item at legal[i]      // i in [0, 57)
```

where `legal` is `ItemStorage2.Machine`: TM ids `191-194, 196-242` (50 entries, note the gaps at
190 and 195) followed by HM ids `243-249` (7 entries). Total 57 = the pouch size.

```csharp
// GetPouch, TMHMs branch
int slot = 0;
for (int i = 0; i < items.Length; i++)
{
    if (data[i] == 0) continue;
    items[slot++] = new InventoryItem { Index = legal[i], Count = data[i] };
}
// SetPouch, TMHMs branch
int index = legal.IndexOf((ushort)item.Index);
if (index < 0) continue;              // enforce correct pouch
data[index] = (byte)item.Count;
```

HMs cap at 1:

```csharp
public override int GetMaxCount(InventoryType type, int itemIndex)
{
    if (type is TMHMs && ItemConverter.IsItemHM2((ushort)itemIndex)) return 1;
    return GetMaxCount(type);
}
```

> **The TM/HM pouch is `itemsAreIdIndexed()`-shaped, the other four are slot-based** — and PKSE's
> `Trainer` base exposes that as **one flag for the whole save**. Gen 2 is the first format where
> the two models coexist in one game. Options, least-bad first:
>
> 1. **Present the TM/HM pouch as a fixed 57-row list** where "removing" sets the count to 0.
>    Keep `itemsAreIdIndexed()` returning `false` and special-case the TM pouch inside
>    `updateItemBlock()`. Least invasive; the UI already hides `count == 0` rows via
>    `visibleItemIndices()`.
> 2. Promote `itemsAreIdIndexed()` to take a pouch index. Cleaner, but touches every game.
>
> Option 1 is what landed: `Trainer2GSC` reads both directions out of the generated
> `Names::getPouchItems(GSC, 0)`.

Legal item sets are `ItemStorage2.General / Balls / KeyGS / KeyCrystal / Machine`, and Crystal has
four extra key items (`070, 115, 116, 129`) that GS does not. `getPouchItems(GSC, pouch)` must
branch on version, not just group.

## 10. Data tables

Gen 2 needs its own tables for the same reasons Gen 1 did. Write **one generator**,
`tools/gen_gen2.py`, emitting `include/Pokemon/Gen2Tables.h` + `src/Pokemon/Gen2Tables.cpp`. Model
it on `tools/gen_gen1.py`.

| Table | Why Gen 2 needs its own | PKHeX source |
|---|---|---|
| **Base stats** | Six stats with a real SpA/SpD split, and many differ from modern values | `PersonalTable.GS` / `.C` (`personal_gs`, `personal_c`) |
| **Gender ratio** | Drives the derived gender **and** Unown handling | same personal table |
| **Types** | Gen 2 predates Fairy/Steel-era renumbering — convert to PKSE's ids **at generation time** | same |
| **Base friendship** | Gen 2 has friendship; the modern table disagrees for some species | same |
| **Move PP** | Gen 2's own PP values; PP Ups add `min(7, base/5)` | `MoveInfo2` |
| **Learnsets** | GS ∪ Crystal level-up, TM/HM, tutor, unioned with pre-evolutions | `lvlmove_gsc.pkl` |
| **Item names** | Gen 2 id space (255 ids), disjoint from modern | PKHeX item string table, index 2 |
| **Item pouch sets** | `ItemStorage2` | `Items/ItemStorage2.cs` |
| **Growth rates** | **Check before reusing.** Gen 1's were verified identical to Gen 3; verify Gen 2 the same way and reuse `Experience.cpp` if they match. | personal table byte |

Two Gen 1 lessons that apply verbatim:

- **PKHeX's personal table byte `0x00` may not be what it looks like.** For `personal_rb` PKHeX
  *substitutes* a gender ratio there. Read `gen_gen1.py`'s handling before assuming the Gen 2
  layout, and assert on the values you get (the gender byte is a small closed set).
- **A species' first moves may live in the personal table, not the learnset.** Verify this for Gen
  2 before shipping; if it holds, omitting them makes every starting move read as unlearnable and
  the transfer sanitizer *deletes* them.

**Species index == National Dex in Gen 2** — this is the one Gen 1 headache you do *not* inherit.
Gen 1's arbitrary internal index (Bulbasaur `0x99`) does not exist here.

    inline constexpr size_t SIZE_2STORED = 32;   // box body
    inline constexpr size_t SIZE_2PARTY  = 48;   // party body -- what a single-entry list carries
    inline constexpr size_t SIZE_2ULIST  = 73;   // 3 + 48 + 11 + 11   international
    inline constexpr size_t SIZE_2JLIST  = 63;   // 3 + 48 +  6 +  6   Japanese

    inline constexpr bool isGen2ListSize(size_t n) noexcept {
        return n == SIZE_2ULIST || n == SIZE_2JLIST;
    }

    inline constexpr uint8_t GEN2_SLOT_EMPTY = 0xFF;
    inline constexpr uint8_t GEN2_SLOT_EGG   = 0xFD;

    public:

        explicit Pokemon2GSC(bool japanese);

        bool   japanese() const noexcept { return dataSize == SIZE_2JLIST; }
        size_t nameLen()  const noexcept { return japanese() ? 6u : 11u; }
        static constexpr size_t ofsBody() noexcept { return 3; }
        size_t ofsOT()   const noexcept { return ofsBody() + SIZE_2PARTY; }   // 51
        size_t ofsNick() const noexcept { return ofsOT() + nameLen(); }

        // ---- BIG ENDIAN byte helpers (copy verbatim from Pokemon1RBY) ----
        uint8_t  rd8(size_t o) const noexcept;
        uint16_t rd16be(size_t o) const noexcept;
        uint32_t rd24be(size_t o) const noexcept;

        void     wr16be(size_t o, uint16_t v) noexcept;
        void     wr24be(size_t o, uint32_t v) noexcept;

        uint16_t speciesID() const noexcept override { return rd8(ofsBody() + 0x00); }
        uint16_t heldItem()  const noexcept override { return rd8(ofsBody() + 0x01); }
        uint16_t move(int slot) const noexcept override {
            return (slot >= 0 && slot < 4) ? rd8(ofsBody() + 0x02 + slot) : 0;
        }
        uint32_t id32()  const noexcept override { return rd16be(ofsBody() + 0x06); }
        uint16_t tid16() const noexcept override { return rd16be(ofsBody() + 0x06); }
        uint16_t sid16() const noexcept override { return 0; }   // Gen 2 has no secret ID
        uint32_t exp()   const noexcept override { return rd24be(ofsBody() + 0x08); }
        uint8_t  friendship() const noexcept override { return rd8(ofsBody() + 0x1B); }

        bool hasNature()       const noexcept override { return false; }
        bool hasAbility()      const noexcept override { return false; }
        bool hasBall()         const noexcept override { return false; }

**`syncListHeader()` must preserve the egg marker**, which is the one place it differs from Gen 1's:

```cpp
void Pokemon2GSC::syncListHeader() noexcept {
    const uint16_t sp = speciesID();
    if (sp == 0) {
        wr8(0, 0);                       // count
        wr8(1, GEN2_SLOT_EMPTY);
    } else {
        wr8(0, 1);
        // Do NOT clobber an egg marker: 0xFD is the only place Gen 2 records "this is an egg",
        // and stamping the species over it hatches the egg silently.
        if (rd8(1) != GEN2_SLOT_EGG) wr8(1, static_cast<uint8_t>(sp));
    }
    wr8(2, 0xFF);                        // list cap -- exactly one, never filled to capacity
}
```

}

### Step 6 — `src/Save/GetSaveFileContents.cpp`

Loose-file I/O is shared by every pre-Switch format: `Save::openExternalSave` runs the
`LOOSE_FORMATS` probe chain and `Save::saveExternalSave` dispatches the write on `getGameGroup()`
with a `static_cast` — adding a format is one row and one `case`. `Save::backupOriginalFile` copies
the **original bytes** to `sdmc:/PKSE/FileBackups` **before** writing. These classes are **not** in
`TrainerVariant`: no title ID, no title-ID dispatch.

### Step 7 — entry point

The file browser OPENS the pick with `Save::openExternalSave` before leaving the picker — the open
is the check — and hands the opened trainer to `UIManager::handleExternalSave`. `Trainer1RBY::detect`
runs before `Trainer2GSC::detect` (PKHeX's probe order).

Sizes overlap: a 32 KiB file could be Gen 1 *or* international Gen 2. The list probes disambiguate,
which is exactly why they are the test.

### Step 8 — entry point, UI, bank

- Add the `LOOSE_FORMATS` row. That is the entry point, and the only thing that exposes the
  format to users. (`isGameSupported` is derived from `getGameGroup` and went true in step 1.)
- `boxGridColumns()` handles 20 and 30 already — **no change**, and the existing `static_assert`s
  already cover both.
- `Names::getItemNameFor()`: add a `GSC` branch (§10).
- `PickerKind`: add `ItemG2` and `PouchItemG2`; add both to `pouchPickerKind()` and — if either
  filters — to the `reorder` list in `drawPickerDialog` ([recipe 3](../manual/09-ui-recipes.md)).
- `Bank.cpp`: `BTAG_GSC = 10`, `BTAG_GSC_JP = 11`. **Two tags**, for the same reason Gen 1 needs
  two: the record's *length* is the only thing that says which locale it is, and the on-disk record
  has no length field. Add-only; never renumber. Also `bankTagForEntity`, `groupForBankTag`,
  `recordSizeFor`.
- **Conversion: `GSC` is not in `inFamily`**, exactly like `RBY`: a Gen 2 Pokemon leaves only
  through the Poke Transporter rule (`isVirtualConsole` in `Conversion::gate`), becoming a PK7, and
  nothing converts back into Gen 2.

### The Pokedex needs NO index table

`Trainer::updatePokedexBlock()` is a no-op for this generation today, and implementing it needs no
generated lookup: PKHeX's `Zukan.cs` puts a species' seen/caught bit at **`species - 1`**
(`GetCaught(species) => GetFlag(OFS_CAUGHT, species - 1)`), so the index is arithmetic. Gen 1, Gen 3
and BDSP already write their dexes this way and carry no table either.

Only games whose dex numbering is ARBITRARY need one — Sword/Shield, Scarlet/Violet and Legends:
Arceus, whose tables are generated, and X/Y through Ultra Sun/Moon, whose FORM region is (see
`tools/gen_dexformtables.py`). If you find yourself wanting a lookup for `species - 1`, you do not
need this file.

## 12. Verification

**The round trip is the gate.**

```bash
python tools/syntax_check.py
python tools/syntax_check.py --warnings
```

Then load a real save and write it back UNEDITED. An editor that cannot reproduce a file it did not
change will corrupt one it did; on Gen 1 this found five bugs, every one PKSE rewriting bytes it had
no business touching.

**A Gen 2 save does NOT come back byte for byte, and that is correct.** Writing refreshes the
trainer-block backup from the primary (§6.3, PKHeX `SAV2.GetFinalData`), and real saves ship with a
stale backup — 211, 250 and 29 bytes moved on three real Gold, Silver and Crystal saves. The rule is
that every byte that moved lies inside a mirror DESTINATION (or is one of the two checksum words),
and afterwards every mirror equals its SOURCE. Those ranges live in `Trainer2GSC::mirrorRegions()`,
which `writeMirrors()` also reads, so the writer and any check cannot disagree. Anything outside
them is a bug; the likely candidates are:

- the `Money + 3` low byte (§8)
- name-field terminator style (`0x50` vs `0x00`) (§7)
- list cap bytes filled to capacity instead of exactly one
- the current-box mirror written when it should not be, or not written when it should (§4.4)
- item-pouch `0xFF` terminators at the wrong index
- TM/HM pouch rewritten as a list instead of positionally (§9)

Then, once the unedited round trip is clean:

- **Stat cross-check**: recompute the five party stats from the tables and compare to what the game
  stored. Proves tables + big-endian reads + DV unpack + formula, all at once.
- **Edit persistence**: change money, OT name, a box name, an item count, and a mon's DVs/EVs/
  nickname; save; reload; check EACH ONE SEPARATELY.
- **Legality**: a Pokemon caught on real hardware must draw NO Invalid finding.

## 13. Trap list

Print this and keep it beside you.

1. **Big endian everywhere.** A byte-swapped read yields a plausible wrong number, not an error.
2. **The save checksum is written LITTLE endian** even though the entity fields are big endian.
3. **The checksum range is inclusive** of `AccumulatedChecksumEnd`.
4. **Gen 2's checksum is a 16-bit sum written twice.** Gen 1's is one inverted byte. Different
   algorithm entirely.
5. **The current-box mirror is not authoritative** — the opposite of Gen 1 (§4.4).
6. **Eggs live in the list header (`0xFD`)**, not in the body. `syncListHeader` must not clobber it.
7. **`SIZE_2STORED` is 32, `SIZE_2PARTY` is 48** — neither matches Gen 1's 33/44.
8. **The box stride is `SIZE_BOX_LIST + 2`**, not `SIZE_BOX_LIST`.
9. **SpA and SpD have different base stats but share one DV and one EV.** The DV/EV setters for SPD
   must be no-ops.
10. **`hasMetData()` is `CaughtData != 0`**, because GS never writes it and `0` is a real met
    location in Crystal.
11. **Money is 3 bytes**; byte `Money + 3` belongs to something else. Preserve it.
12. **The TM/HM pouch is positionally indexed**, the other four are lists, and Key Items are ids
    without counts.
13. **Crystal has four key items GS does not.** Branch the legal set on version.
14. **Gold and Silver are indistinguishable.** Name the pair. Do not guess from the filename — a
    Virtual Console backup is just `sav.dat`. Same call PKSE already made for Red/Blue.
15. **Korean is GS-only**, has 17-byte box names, double-width strings, and its own checksum.
16. **Preserve the existing name terminator style** (`0x50` vs `0x00`).
17. **Mirror regions must be rewritten on save** (§6.3), and *after* `SetChecksums()`.
18. **Japanese Gen 2 is 64 KiB**, not 32. Japanese Gen 1 is 32.
19. **Species index == National Dex.** Do not port Gen 1's index-conversion table.
20. **A `nullptr` learnset means "no data", not "learns nothing."** The transfer sanitizer deletes
    what `isLearnable()` denies.
